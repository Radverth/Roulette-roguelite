# Sin Wheel — Pixel Art Asset Set

All sprites are drawn at **native resolution** and locked to a **32-colour
palette**. Nothing is anti-aliased, nothing is downsampled, and no sprite
contains a colour outside the palette — this is verified at generation time.

## Import settings (Unity)

Apply to every sprite in this folder:

| Setting | Value |
|---|---|
| Texture Type | Sprite (2D and UI) |
| Filter Mode | **Point (no filter)** |
| Compression | **None** |
| Pixels Per Unit | 16 |
| Max Size | ≥ native size |
| Generate Mip Maps | Off |

Scale the camera / canvas by **integer factors only** (×4, ×6, ×8). Any
fractional scale destroys the pixel grid.

## Wheel layout

Wedge order is authored, not random. Risk wedges sit at indices 1, 4, 7 and 10
so no two are ever adjacent — otherwise the wheel develops a visually dead half.
See `Wheel/segment_layout.txt`.

Seams beside a risk wedge are drawn in bright brass rather than dark, so the
danger edge is felt before it is read.

## Palette

32 entries, see `Branding/palette_32.png`. Index ranges:

- `0–6` cold neutral ramp (void → slate)
- `7–10` bone ramp
- `11–14` cold brass
- `15–17` wine
- `18–24` sin base colours, in canonical order
- `25–31` sin highlights, same order

Sin order throughout: pride, greed, wrath, envy, lust, gluttony, sloth.

## Regenerating

Everything here is generated by the scripts in `/Tools`. Edit and re-run:

```bash
python3 Tools/gen_wheel_px.py
python3 Tools/gen_icons_sigils_px.py
python3 Tools/gen_ui_px.py
```

`palette32.py` holds the palette, the indexed canvas, ordered dithering and the
pixel-map parser. Adding a colour there is the only way to add a colour.
